Why this structure is valuable

1 · Guarantees live in the database, not the app.
Tenant isolation, role limits, append-only ledgers — all enforced by Postgres itself. A buggy screen, a malicious API call, even a future mobile app can't bypass them. The migrations folder is the product's trust story, in ~500 auditable lines.
2 · Every guarantee has a test with its name on it.
Migration 001 pairs with test 001, 002 with 002, 003 with 003. When an investor asks "how do I know the numbers are real?", the answer is a named file with 36 assertions that run on every single change.
3 · One door to the money.
No screen computes a dollar figure. Everything flows through financials.ts → the server-side engine. Two screens can never disagree — the class of bug that kills trust in spreadsheet-run flips is structurally impossible.
4 · Live and preview pages are separate files.
live.tsx is real; preview.tsx is the concept vision with an honest amber pill. Phases 3–5 are executed by moving pages from one file to the other — the roadmap is literally visible in the file structure.

3 · What each phase added

Each layer builds strictly on the one before it — the portfolio math is only trustworthy because the ledger beneath it is append-only, which is only meaningful because tenancy and roles beneath that are database-enforced.
