FlipScope — Build Plan

Property-to-profit management platform · Engineering roadmap · 2026-08-18

What FlipScope is. A platform that takes a real-estate flip from the first property walkthrough to verified profit: capture the walkthrough once, turn it into a priced scope of work, design the finished space, run the job on schedule with proof-of-work verification, and keep budget, cost, and ROI live and correct throughout — across an entire portfolio of properties. This plan covers the build from the current prototype to a production release, organized around three milestones: MVP → Beta → Production.

1 · System architecture

FlipScope is a web application backed by a managed Postgres platform (Supabase), with an AI service layer reached only through server-side functions so no keys or model calls ever live in the browser.

Client talks to the database directly for ordinary reads/writes (guarded by row-level security) and routes any sensitive or AI work through server functions.

Correctness & security baked in from day one

  • One financial engine. All money stored as integer cents; a single server-side model computes budget, committed, actual, profit and ROI so every screen shows the same numbers.
  • Tenant isolation. Row-level security gates every table on organization membership, then role. Verified by an automated policy test suite in CI.
  • Proof-chain media. Photos and video stored with uploader, timestamp and location; they persist and back the verification trail.
  • Audit log. Append-only record of every change — the backbone of approvals and investor trust.
  • Separate environments. Development, staging and production run on isolated databases.

2 · Tenancy & data model

The account structure is multi-tenant from the first line of code, so the platform can run one organization’s portfolio today and many organizations later without re-architecture.

Every row carries an organization id; access policies check organization membership first, then role. A project holds the scope, schedule, financials, field logs and closeout for one rehab.

3 · The AI capture pipeline

The signature feature: walk the property once, talking naturally, and get a priced, editable scope of work back — no manual line-item entry. This is what sets FlipScope apart from a spreadsheet.

The same service layer powers the project-aware Copilot (questions about cost, cash, schedule and risk) and the AI Designer (real room re-design renders). Everything runs server-side.

4 · Milestones & roadmap

The six phases roll up into three release milestones. A milestone is a readiness bar, not just “phases done” — each has a gate that must be met before the next milestone begins.

Approximate timeline — 6 phases across ~17 weeks, gated into three releases.

MILESTONE 1  MVP — Internal Use

Phases 0–2 · ~6–7 weeks

The smallest version that is genuinely production-grade: a real, secure app with trustworthy numbers that a portfolio can be run on.

2–3 wks

Phase 0 — Foundation

React/TypeScript app scaffold · multi-tenant schema (Org → Portfolio → Property → Project) · money-in-cents & single financial engine · dev/staging/prod split · CI with tenant-isolation tests.
2 wks

Phase 1 — Trust, roles & evidence

Role-based access · append-only audit log · persistent proof-chain media · read-only investor view.
2 wks

Phase 2 — Portfolio layer

Cross-property rollups · blended ROI · combined cash-flow calendar · risk heatmap · deal greenlight view.
MVP gate. The portfolio can be run internally on live deals: multiple properties under one organization, every financial figure consistent to the cent, proof photos that persist, and a working portfolio rollup view.

MILESTONE 2  Beta — Feature-Complete

Phases 3–4 · ~4–7 weeks

The differentiators land and the tool connects to the outside world; a wider set of users runs it on real projects.

2–4 wks

Phase 3 — AI scope capture & Copilot

Walkthrough → transcription → structured, priced scope · project-aware Copilot · forecast/risk computed from live project state.
2–3 wks

Phase 4 — Integrations

Comps/ARV data feed (replaces typed-in ARV) · e-signature for change orders & approvals · SMS/email notifications · accounting sync.
Beta gate. A recorded walkthrough produces an editable, priced scope end-to-end; ARV pulls from real comparables; a change order is approved with a binding signature; a small group beyond the core team uses it without hand-holding.

MILESTONE 3  Production — General Availability

Phase 5 + hardening · ~3–4 weeks

Reliability, field readiness and polish to a bar that supports daily on-site use and future external organizations.

3–4 wks

Phase 5 — Field, Designer & readiness

Field PWA with offline capture & conflict-safe sync · real AI Designer (room re-design renders) · performance/security hardening · dormant onboarding scaffolding for additional organizations.
Production gate. Crews work offline on-site and sync cleanly; the Designer produces real redesigned imagery; security and performance targets are met; a second organization could be provisioned within a day.

5 · What’s needed to start Phase 0

  • A dedicated Supabase project (schema, security policies and migrations set up as part of Phase 0).
  • The first organization’s details — initial members & roles, and the first property/portfolio to seed.
  • Access to the AI service endpoints the platform will call (transcription, LLM, image pipeline).
  • A source repository with continuous integration.
